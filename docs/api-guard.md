# APIの守り方

公開している2つのAPIに入れてある守りと、まだ残っている弱点です。`app/api/` を変える前に読みます。

| API | 何をするか | 守る理由 |
|---|---|---|
| `/api/sports-guide` | 質問を受けて OpenAI を呼び、回答を返す | 呼ばれるたびに費用がかかる |
| `/api/feedback` | フォームの内容を保存する | 氏名、メール、電話番号、住所を受け取る |

## AIガイドの一時停止

`/api/sports-guide` は、**既定で止まっています。** 環境変数 `SPORTS_GUIDE_ENABLED` が `true`（または `1`）のときだけ動きます。

- 停止中は、OpenAI を呼ばずに 503 と案内文を返す。ページは、入力欄の代わりに同じ案内文を出す。
- 再開するには、Vercel の環境変数に `SPORTS_GUIDE_ENABLED=true` を設定して、デプロイし直す。手元で試すときは `.env.local` に書く。
- もう一度止めるには、その環境変数を消して、デプロイし直す。
- スイッチと案内文は `lib/study/guide-availability.ts` にある。

再開する前に、OpenAI 側の利用上限を設定しておく（`state/tasks.json` の T007、T013）。

## 入れてある守り

処理の順に並べています。どれかに当たると、その先には進みません。`/api/sports-guide` では、一時停止の判定がこの前にあります。

1. ほかのサイトのページから、ブラウザ経由で呼ばれたら断る（403）。
2. JSON 以外の送信は断る（415）。
3. 本文が大きすぎたら断る（413）。上限は、質問が 4KB、フィードバックが 100KB。
4. 入力の型と長さを確かめる（400）。質問は500文字まで。フィードバックの上限は `lib/security/validate.ts` の `FEEDBACK_LIMITS`。
5. 回数制限に当たったら断る（429）。断った呼び出しは回数に数えない。

| API | 送信元ごと | 全体 |
|---|---|---|
| `/api/sports-guide` | 1分に5回、1日に30回 | 1分に20回、1日に300回 |
| `/api/feedback` | 1分に5回、1日に30回 | 1分に60回、1日に1,000回 |

`/api/sports-guide` には、さらに次の守りがあります。

- OpenAI に頼む出力の長さに上限を付けている（`max_tokens` が 1,500）。
- OpenAI の応答を25秒で打ち切る。
- APIキーが未設定のときは、OpenAI を呼ばずに 503 を返す。
- フィードバックの要約は AI への指示文に入る。画面で選べる値だけを数え、利用者が送った文字列は入れない（`lib/study/feedback.ts`）。

数字を変える場所は、各 `route.ts` の先頭です。

## 残っている弱点

- **回数制限はメモリ上にある。** サーバーレスではインスタンスごとに別々に数えるので、インスタンスが増えると上限を超えられる。再起動でも数え直しになる。
- **費用の本当の上限にはならない。** OpenAI の管理画面で、このキーに利用上限を設定する（`state/tasks.json` の T007）。
- **Vercel のプロジェクトが2つある。** それぞれに公開のURLがあり、回数制限は別々に数える（T012）。
- **ブラウザ以外からの呼び出しは、1番では止まらない。** 回数制限だけが効く。
- **Vercel 以外で動かすと、送信元を偽られることがある。** その場合も全体の上限は効く。
- **フィードバックの保存先はファイルのまま。** Vercel の関数には書き込める永続的なファイルシステムがないので、保存できていない可能性がある（T008）。

## 確かめ方

```
npm test
```

回数制限、入力の検証、要約の集計を確かめます。Next.js を通した動作（実際のURLへの送信）は、このテストでは確かめていません。
