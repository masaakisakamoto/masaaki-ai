# 0002 APIの回数制限をメモリ上で行う

- 日付：2026-11-12
- 状態：提案（このファイルを含むプルリクエストのマージで採用）

## 背景

`/api/sports-guide` は、認証も回数制限もなく OpenAI を呼んでいた。URL を知っていれば、誰でも費用を使わせられる状態だった。`/api/feedback` も、型や長さを確かめずに保存していた。

## 決めたこと

外部のサービスも追加の依存も使わず、メモリ上の回数制限と入力の検証を入れる。送信元ごとの上限に加えて、全体の上限を持つ。出力の長さにも上限を付ける。

## 選ばなかった案

- 外部の保存先（Redis など）を使った回数制限：インスタンスをまたいで正確に数えられる。ただし、新しいサービスの契約、鍵の管理、依存の追加が必要になる。今の利用規模では、先に穴をふさぐことを優先した。
- Vercel のファイアウォールの回数制限：コードを変えずに入れられる。プランと設定に依存するので、コード側の守りと併用する候補として残す。
- ログインを必須にする：公開の案内ページという目的に合わない。

## 影響

- 1つのインスタンスの中では、上限を超える呼び出しを断れる。
- インスタンスをまたぐ上限にはならない。費用の上限は、OpenAI 側の利用上限で別に設定する必要がある。
- 利用が増えて、正確な上限が必要になったら、外部の保存先を使う方式に置き換える。そのときは新しい記録を足す。
