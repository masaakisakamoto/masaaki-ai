# state/ 作業の状態

エージェントと人が、作業の状況を引き継ぐための場所です。

| パス | 役割 |
|---|---|
| `tasks.json` | 複数回の作業にまたがる仕事を、小さく分けた一覧 |
| `progress/` | 引き継ぎメモ。1回の作業につき1ファイル |

仕事の入口は課題管理（Linear や GitHub Issues）です。1回のプルリクエストで終わる課題は、`tasks.json` に書く必要はありません。

## tasks.json

| 項目 | 意味 |
|---|---|
| `id` | 変えない識別子 |
| `title` | 何をするか |
| `risk` | `low`、`medium`、`high` のどれか。定義は [../docs/risk-tiers.md](../docs/risk-tiers.md) |
| `status` | `todo`、`doing`、`done`、`blocked` のどれか。エージェントが書き換えてよいのはここだけ |
| `executor` | `agent` はエージェントが自分で取ってよい。`human` は人が進める |
| `verify` | 終わったと言える条件。確かめ方を具体的に書く |
| `notes` | 補足（なくてもよい） |

決まり：

- `risk` が `high` のタスクは、`executor` を `human` にする。
- タスクの追加、削除、書き換えは人が行う。
- 並行して任せるときは、セッションごとにタスクの `id` を指定する。同じタスクを2つのエージェントが取らないようにするためです。

## progress/

作業が途中で終わるとき、または次の人やエージェントが知るべきことがあるときに、1ファイル足します。

- ファイル名は「日付-短い名前.md」。例：`2026-11-12-T005-add-tests.md`
- 既にあるファイルは書き換えない。1回の作業につき1ファイルにしておくと、並行作業でも衝突しません。
- 読むときは、ファイル名の順で最後の3件から。

書くこと：

```markdown
# 2026-11-12 T005 テストの追加

- やったこと：
- 確かめたこと：（実行したコマンドと結果）
- 確かめられなかったこと：
- 次にやること：
```

古いメモは、ときどきまとめて消してかまいません。git の履歴に残ります。
